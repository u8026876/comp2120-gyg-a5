# Presentation authoring instructions

This folder applies only to the COMP2120 A4 presentation kit. The human request takes precedence. These are visual and evidence instructions, not new approval gates.

## Required inputs

Read README.md and design-tokens.json. Inspect COMP2120-A4-warm-template.pdf or preview.png before changing a slide. Use COMP2120-A4-warm-template.pptx as the editable source. Claude users should follow these same instructions.

## Authoring

- Duplicate and populate a supplied native slide; preserve its 16:9 size, typography, margins and meaning-bearing structure.
- Use the approved forest, warm paper, terracotta and sage palette exactly. Do not substitute a generic white/blue theme or reproduce an older cream/teal deck.
- Narrative font: Manrope. Technical text: Roboto Mono. Preserve template sizes. If a required font is unavailable, report that before substituting it.
- Keep one clear purpose per slide. Use a large input, code excerpt or actual evidence as the main visual when it helps explain the issue.
- Keep native text editable. Do not flatten the slide into an image. A screenshot may remain an image; fit it without cropping meaningful content or distorting its aspect ratio.
- Replace every prompt in the slides you deliver. Remove unused library slides and the guide from the final section. Do not change another member's section.
- Prefer concise text and source-bearing speaker notes. Use a different supplied layout or shorten wording before shrinking type.
- Avoid repeated card grids, pills, drop shadows, arbitrary icons and decorative stock imagery. The visual subject is the member's actual work.

## Facts, ownership and notes

- Use the member's real contribution and evidence. Ask for missing facts; do not invent results, reviews, dates, claims of understanding or upstream status.
- The completed TIKA-4431 PNG is a style example belonging to Kyubin. Do not present it as another member's work.
- Record the author, collaborators, AI assistance, issue/commit/PR sources, exact test scope and material limitations.
- Distinguish local tests, remote CI, group review, group PR, upstream PR and merge.
- Include a suggested speaking script and duration in speaker notes. About 55 seconds is a planning target; coordinate extra time with the group.

## Delivery

Return an editable PPTX section and a rendered PDF or PNG preview. Inspect every delivered slide for font substitution, overflow, clipping, overlap and screenshot distortion. A successful export alone is not visual verification.

Keep this folder out of Apache-bound PRs. Do not submit assessed work or post messages merely because this file exists; follow the human's authorization.
